# 🎼 المايسترو — منصة توصيل مربوطة بالمطاعم

نظام دليفري متكامل، شبيه بتطبيقات التوصيل الكبيرة، لكن خاص بيك أنت (المايسترو). العميل يطلب من تطبيق الموبايل، المطعم بياخد إشعار فوري على لوحة تحكم الويب بتاعته، يوافق، وتتطبع ورقة الأوردر تلقائي من طابعة الكاشير — وموقع العميل (لوكيشن جوجل ماب) بيتبعت أوتوماتيك مع كل طلب.

## الفكرة والهوية البصرية

الهوية مبنية على شعار **MAESTRO — Fast Delivery**: خلفية سودة، حرف M مزدوج أبيض بولد، وبرق أصفر كهربائي بيقطع في النص، بيعبّر عن السرعة والطاقة. الألوان:

| العنصر | اللون | الاستخدام |
|---|---|---|
| أسود المسرح | `#0D0D0D` | الخلفية الأساسية |
| أصفر البرق | `#FFC700` | اللون المميز، الأزرار الرئيسية، الشعار |
| أبيض | `#FFFFFF` | النصوص والحرف M في اللوجو |
| أخضر | `#2ECC71` | حالات "تم القبول/التسليم" |
| رمادي فاتح للنصوص الثانوية | `#A9A9AE` | نصوص مساعدة |

الخطوط: **Cairo** بوزن 900 (عناوين بولد جريئة)، **Tajawal** (نصوص)، **IBM Plex Mono** (أرقام الأوردرات والوقت).
اللوجو موجود كمكوّن SVG قابل لإعادة الاستخدام في كل مكان: `restaurant-web/src/components/Logo.jsx` (ويب) و `mobile-app/src/components/Logo.jsx` (موبايل، عبر `react-native-svg`)، وكمان فيه شاشة splash بافتتاحية سودة مع اللوجو (`mobile-app/src/screens/SplashScreen.jsx`).
العنصر المميز (Signature): تأثير "نبضة البرق" (Bolt Pulse) — لما أوردر جديد يوصل، الكارت بينبض بحلقة صفراء لمدة ثانيتين، ومسار حالة الأوردر متصمم كخطوات لحظية (♩ ♪ ♫ ⚡ ✓).

## هيكل المشروع

```
maestro-delivery/
├── backend/            # Node.js + Express + Socket.io — العقل المدبر للنظام
├── restaurant-web/      # React (Vite) — لوحة تحكم المطعم (استقبال/موافقة/طباعة)
└── mobile-app/          # Expo (React Native) — تطبيق العميل (طلب + موقع + تتبع)
```

## إزاي كل حاجة شغالة

1. **العميل** يفتح تطبيق الموبايل، يختار مطعم، يعمل طلبه.
2. عند التأكيد، التطبيق **يجيب موقع الـ GPS بتاعه أوتوماتيك** (بإذن العميل) ويبعته مع الطلب كـ `lat/lng` + رابط جوجل ماب جاهز.
3. الطلب يوصل للباك إند، اللي **يبعت إشعار Real-time فوري (Socket.io)** لداشبورد المطعم بس (المطعم صاحب الطلب).
4. صاحب المطعم يشوف الطلب في لوحته، يضغط **"قبول وطباعة"**.
5. النظام **يطبع أوتوماتيك ورقة أوردر** — إما عن طريق نافذة طباعة المتصفح (تشتغل مع أي طابعة كاشير متظبطة كـ default على جهاز الكاشير)، أو مباشرة لطابعة شبكة حرارية (ESC/POS) لو مفعّل وضع `network` وحطيت IP الطابعة.
6. العميل يتابع حالة طلبه لحظة بلحظة (قيد الانتظار ← تم القبول ← التحضير ← في الطريق ← تم التسليم) على شاشة التتبع.

## تشغيل المشروع محلياً

### 1) الباك إند

```bash
cd backend
npm install
cp .env.example .env     # وعدّل القيم لو محتاج
npm run dev              # يشتغل على http://localhost:4000
```

بيانات تجريبية جاهزة في `backend/data/db.json`: مطعمين (كود الدخول `1234` و `5678`).

### 2) لوحة تحكم المطعم (ويب)

```bash
cd restaurant-web
npm install
npm run dev               # يفتح على http://localhost:5173
```

سجّل دخول بكود `1234` (كشري مصر) أو `5678` (بيت المشويات) وجرب تبعت أوردر من الموبايل/الـ API وشوفه بيوصل لحظياً.

### 3) تطبيق العميل (موبايل)

```bash
cd mobile-app
npm install
npx expo start
```

افتحه على المحاكي أو حمّل تطبيق **Expo Go** وامسح الـ QR كود. لازم توافق على إذن الموقع عشان الطلب يتبعت.

> **ملحوظة مهمة:** لو بتجرب على موبايل حقيقي أو محاكي مختلف عن جهاز السيرفر، غيّر `apiBase` في `mobile-app/app.json` و `VITE_API_BASE` في `.env` بتاع `restaurant-web` من `localhost` لعنوان الـ IP بتاع جهاز السيرفر على نفس الشبكة (مثلاً `http://192.168.1.10:4000`).

## ربط طابعة كاشير حقيقية

الوضع الافتراضي (`browser`) بيفتح نافذة طباعة عادية من لوحة تحكم المطعم — ده بيشتغل مع أي طابعة (حرارية أو عادية) متظبطة كـ Default Printer على جهاز الكاشير، من غير أي إعداد إضافي.

لو عايز طباعة مباشرة (Network/ESC-POS) من غير ما تعدي على نافذة المتصفح:
1. افتح `backend/data/db.json`.
2. غيّر `printer.mode` للمطعم المطلوب لـ `"network"` وحط الـ IP بتاع الطابعة في `printer.ip`.
3. الباك إند هيستخدم مكتبة `node-thermal-printer` (الكود جاهز في `backend/src/print.js`) ويبعت الإيصال مباشرة.

## ربط جوجل ماب فعلي

دلوقتي الرابط اللي بيتبعت هو رابط جوجل ماب مباشر (`google.com/maps?q=lat,lng`) وده شغال من غير أي API key. لو عايز تعرض **خريطة مصغّرة جوّه لوحة تحكم المطعم** بدل الرابط بس، هتحتاج `GOOGLE_MAPS_API_KEY` (موجود مكانه جاهز في `backend/.env.example`) وتستخدمه في مكوّن خريطة زي `react-google-maps` جوه `restaurant-web`.

## الخطوات الجاية المقترحة

- إضافة تطبيق موبايل منفصل بسيط للـ **دليفري/الكابتن** (استلام الأوردر بعد "خرج للتوصيل" + تحديث موقعه لحظياً للعميل).
- قاعدة بيانات حقيقية (Postgres/MongoDB) بدل ملف JSON، ده مناسب بس للتجربة والتطوير.
- نظام تسجيل دخول حقيقي (JWT) بدل كود المطعم البسيط.
- ربط بوابة دفع (فوري/بايمنت) لو هتقبل دفع أونلاين مش بس كاش عند الاستلام.

## 🆕 التحديثات الجديدة (v2)

المشروع بقى فيه دلوقتي:

- **قاعدة بيانات حقيقية** (SQLite عبر `better-sqlite3`) بدل ملف JSON — تدعم عدة عمليات في نفس الوقت وأمان أكتر. الملف بيتخزن في `backend/data/maestro.db` (متضاف في `.gitignore`).
- **تسجيل دخول حقيقي بـ JWT** لكل من: المطعم، الأدمن، والكابتن — الباسوردات متخزنة مشفّرة (`bcryptjs`).
- **لوحة تحكم أدمن** (زرار "دخول كأدمن" في شاشة تسجيل دخول المطعم) — بيانات الدخول الافتراضية: `admin` / القيمة اللي حطيتها في `ADMIN_DEFAULT_PASSWORD`. من اللوحة دي تقدر تضيف مطاعم جديدة، تضيف/تشيل أصناف المنيو، وتظبط وضع الطابعة لكل مطعم.
- **تطبيق كابتن/دليفري منفصل** في `captain-app/` (Expo) — الكابتن يسجل دخول بكود `9999` وباسورد `9999` (ديمو)، يشوف الأوردرات الجاهزة للتوصيل، يستلم أوردر، ويحدّث حالته (خرج للتوصيل ← تم التسليم). أثناء "خرج للتوصيل" بيبعت موقعه GPS لحظيًا، والعميل بيشوف لينك يتابع بيه مكان الكابتن دلوقتي.
- **إشعارات Push حقيقية** عبر خدمة Expo المجانية — تتبعت للعميل مع كل تغيير في حالة الأوردر حتى لو التطبيق مقفول (تحتاج بناء فعلي على جهاز، مش هتشتغل في محاكي الويب).
- **حماية أساسية للـ API** (rate limiting) عشان محدش يقدر يبعت طلبات وهمية بكثرة.
- **الدفع**: كاش عند الاستلام فقط دلوقتي (تم تأجيل بوابة الدفع الإلكتروني بناءً على طلبك).

### الديبلوي

فيه ملف `render.yaml` جاهز في جذر المشروع — من Render اختار "New > Blueprint" ووجهه للريبو، وهيجهز الـ backend + لوحة تحكم المطعم أوتوماتيك. هتحتاج بس تحط قيمة `ADMIN_DEFAULT_PASSWORD` و `GOOGLE_MAPS_API_KEY` (اختياري) في إعدادات الـ environment variables بعد أول ديبلوي.

### لسه ناقص (لو حبيت تكمل لاحقًا)
